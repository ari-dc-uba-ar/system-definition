## Quinto rojo propuesto — parámetros tipados y transporte de codecs

Este slice fija `migration_parameters` y el transporte tipado desde valores de máquina, usando el `PersistenceInfo` y el `StorageContext` reales del consumidor. El registro físico se amplía conceptualmente con `machineCodecs`, un contrato por tipo físico con `readExpression` y `transportType`; la implementación de esa ampliación queda bloqueada hasta aprobación de este rojo.

El test `compile-data-parameters-test.ts` exige:

1. materializar `migration_parameters` como una relación temporal determinística de una sola fila, con columnas ordenadas de forma estable y valores enviados como parámetros del driver, nunca interpolados como literales SQL;
2. preservar `null`, `''` y el texto `'null'` como valores de transporte distintos;
3. resolver cada dominio lógico mediante `persistence.representations[storage.representation]` antes de consultar `physicalTypes`/`machineCodecs`, de modo que un tipo de dominio como `email` pueda usar el contrato físico `text`;
4. fallar antes de invocar el rewriter SQL si falta el mapping físico, el codec o el `transportType` referenciado.

Este rojo no autoriza todavía la proyección SQL de filas a representación de máquina mediante `readExpression`, la ejecución de validadores históricos sobre lecturas SQL, conservation checks, inserts/`whenMissing=insert` ni checkpoints del runner. Esos límites tendrán reds posteriores.

Contra la implementación actual, TypeScript debe permanecer limpio y los cuatro casos de `T20 typed migration parameters and codec transport` deben fallar en runtime porque `compile-data.ts` todavía bloquea cualquier transformación con parámetros tipados. En los tres casos positivos se espera la frontera actual `typed transformation parameters are not part of this compiler slice`; el caso negativo debe fallar porque todavía recibe esa frontera genérica en lugar del error concreto de mapping/codec/transport.

No se autoriza producción de este quinto slice hasta aprobación explícita del rojo.
