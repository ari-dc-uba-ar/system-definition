# Evidencia T17 — CLI, CI y documentación del motor

## Alcance

T17 integra T01–T16 en una CLI operativa y completa el build/CI/documentación del consumidor sin crear un segundo runner. Esta tarea no implementa todavía la autoría/resolución de T18–T23; esas tareas extenderán la misma integración posteriormente.

La aceptación de T17 sigue `implementacion-migraciones.md` §§15 y 19 y `migraciones-contratos.md` §11: éxito completo usa exit code 0; entrada/configuración inválida usa 2; verificación/gate bloqueado usa 3; fallo operativo o commit desconocido usa 4. Todo código distinto de cero bloquea el job dependiente. PostgreSQL distinto de 18.6 o no disponible debe fallar, no producir un skip exitoso.

## Reutilización

- **R:** `Problem`/`ValidationResult` del paquete raíz para resultados y problemas de CLI.
- **R:** entrypoints y funciones de biblioteca ya implementadas en T01–T16; la CLI delega y no reimplementa runner, verificador, journal ni gate.
- **R:** scripts TypeScript/Mocha existentes del root y consumidor, exports públicos y workflow reusable actual.
- **P:** T17 sólo expone en su primer contrato los comandos ya materializables con T01–T16; T18–T23 ampliarán autoría/resolución sobre la misma frontera.
- **N:** `consumers/postgres-migrations/src/cli.ts`, scripts de integración/CI y documentación operativa del consumidor.

## Primer rojo — frontera CLI

Se agregan, sin código de producción:

- `consumers/postgres-migrations/test/cli-contract-test.ts`;
- `consumers/postgres-migrations/test/cli-test.ts`.

El contrato fija el conjunto T17 disponible antes de las extensiones de autoría: `capture`, `build-release`, `verify`, `publish`, `plan`, `status`, `install`, `apply` y `deployment-gate`.

El rojo exige:

1. tipos exactos `CliCommand` y `CliExitCode = 0 | 2 | 3 | 4`;
2. `cliExitCode` clasifica éxito, entrada/configuración inválida, bloqueo de verificación/gate y fallo operativo/commit desconocido en las cuatro categorías técnicas documentadas;
3. `runCliCommand` recibe un executor de biblioteca, lo invoca exactamente una vez con el comando/argumentos intactos y devuelve el mismo `ValidationResult`, agregando sólo el código técnico;
4. este borde no contiene un segundo runner ni transforma un fallo de biblioteca en éxito.

En el estado previo a T17 no existe `consumers/postgres-migrations/src/cli.ts`, por lo que el rojo esperado es de compilación: ambos tests nuevos deben fallar con `TS2307` para `../src/cli`. No se agrega un stub ni implementación antes de la revisión del desarrollador.

## Primera ejecución del rojo — 2026-09-29

Comando ejecutado por el desarrollador:

```powershell
docker compose exec node `
  npm --prefix consumers/postgres-migrations test
```

Resultado: no cero, como corresponde a un rojo. Aparecieron los dos fallos contractuales esperados:

- `test/cli-contract-test.ts`: `TS2307 Cannot find module '../src/cli'`;
- `test/cli-test.ts`: `TS2307 Cannot find module '../src/cli'`.

La misma compilación produjo además dos `TS7006` en los parámetros `command` y `args` del executor del test. Son ruido incidental: al no poder resolver `CliCommandExecutor` desde el módulo todavía inexistente, TypeScript pierde el tipado contextual de esa lambda. No expresan un segundo requisito de producción.

Antes de solicitar aprobación del rojo se anotan explícitamente esos dos parámetros en el test, sin agregar código productivo. La siguiente ejecución debe conservar sólo los dos `TS2307` deliberados.

## Aprobación e implementación de la primera frontera — 2026-09-29

El desarrollador aprobó explícitamente el rojo con `T17 red approved`. No se recibió una segunda transcripción del rojo después de limpiar los `TS7006`; la aprobación explícita autoriza igualmente esta primera implementación y queda registrada sin inventar una ejecución no aportada.

La autorización se limita al contrato ya revisado; no habilita todavía cambios de CI, integración PostgreSQL 18.6 ni documentación.

Implementación mínima en `consumers/postgres-migrations/src/cli.ts`:

- `CliCommand` contiene sólo los nueve comandos disponibles en la frontera T01–T16 aprobada;
- `CliExitCode` es exactamente `0 | 2 | 3 | 4`;
- `cliExitCode` devuelve 0 sólo para `ValidationResult.ok`; clasifica entrada/configuración en 2, verificación/gate en 3 y deja fallos operativos o message keys no reconocidas en 4, de modo que un fallo nuevo nunca se convierta accidentalmente en éxito;
- si un resultado contiene problemas de clases distintas, prevalece `4`, luego `3`, luego `2`;
- `runCliCommand` invoca una sola vez el executor de biblioteca y devuelve exactamente el mismo `ValidationResult` junto con el código técnico; no introduce un runner alternativo.

Validación local no autoritativa de esta preparación:

- compilación estricta aislada de `src/cli.ts` y los dos tests de contrato con TypeScript disponible en el entorno: sin diagnósticos;
- smoke runtime de los cinco casos del test (`0/2/2/3/4`) y delegación única: correcto.

La verificación autoritativa sigue siendo la ejecución del repo en Docker Node 24 aportada por el desarrollador.

## Verde autoritativo de la primera frontera — 2026-09-29

El desarrollador ejecutó primero el chequeo explícito de integridad TypeScript del consumidor:

```powershell
docker compose exec node `
  npx tsc `
  -p consumers/postgres-migrations/tsconfig.json `
  --noEmit
```

El comando volvió al prompt sin diagnósticos. A continuación ejecutó:

```powershell
docker compose exec node npm test
```

Resultados aportados:

- núcleo: **146 passing**;
- `migration CLI boundary`: **2 passing**, cubriendo mapeo `0/2/3/4` y delegación única;
- consumidor `@system-definition/postgres-migrations`: **58 passing**;
- total del recorrido raíz: **204 tests passing**.

El `npm test` raíz compila primero el núcleo y después el consumidor; en el consumidor `test` ejecuta `tsc` antes de Mocha. Por tanto el verde aportado cubre tanto regresión completa como compilación/ejecución de los dos tests de la primera frontera CLI.

Esta evidencia verifica **sólo la primera frontera CLI aprobada**. No marca T17 completa como verificada: CI Windows/Linux, integración real PostgreSQL 18.6 y documentación generada siguen pendientes de rojo/revisión/implementación.
