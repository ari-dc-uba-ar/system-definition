# Evidencia T17 — CLI, CI y documentación del motor

## Alcance

T17 integra T01–T16 en una CLI operativa y completa el build/CI/documentación del consumidor sin crear un segundo runner. Esta tarea no implementa todavía la autoría/resolución de T18–T23; esas tareas extenderán la misma integración posteriormente.

La aceptación de T17 sigue `implementacion-migraciones.md` §§15 y 19 y `migraciones-contratos.md` §11: éxito completo usa exit code 0; entrada/configuración inválida usa 2; verificación/gate bloqueado usa 3; fallo operativo o commit desconocido usa 4. Todo código distinto de cero bloquea el job dependiente. PostgreSQL distinto de 18.6 o no disponible debe fallar, no producir un skip exitoso.

## Reutilización

- **R:** `Problem`/`ValidationResult` del paquete raíz para resultados y problemas de CLI.
- **R:** entrypoints y funciones de biblioteca ya implementadas en T01–T16; la CLI delega y no reimplementa runner, verificador, journal ni gate.
- **R:** scripts TypeScript/Mocha existentes del root y consumidor, exports públicos y workflow reusable actual.
- **P:** T17 sólo expone en su primer contrato los comandos ya materializables con T01–T16; T18–T23 ampliarán autoría/resolución sobre la misma frontera.
- **N:** `consumers/postgres-migrations/src/cli.ts`, scripts de integración/CI y documentación operativa del consumidor.

## Primer rojo — frontera CLI

Se agregan, sin código de producción:

- `consumers/postgres-migrations/test/cli-contract-test.ts`;
- `consumers/postgres-migrations/test/cli-test.ts`.

El contrato fija el conjunto T17 disponible antes de las extensiones de autoría: `capture`, `build-release`, `verify`, `publish`, `plan`, `status`, `install`, `apply` y `deployment-gate`.

El rojo exige:

1. tipos exactos `CliCommand` y `CliExitCode = 0 | 2 | 3 | 4`;
2. `cliExitCode` clasifica éxito, entrada/configuración inválida, bloqueo de verificación/gate y fallo operativo/commit desconocido en las cuatro categorías técnicas documentadas;
3. `runCliCommand` recibe un executor de biblioteca, lo invoca exactamente una vez con el comando/argumentos intactos y devuelve el mismo `ValidationResult`, agregando sólo el código técnico;
4. este borde no contiene un segundo runner ni transforma un fallo de biblioteca en éxito.

En el estado previo a T17 no existe `consumers/postgres-migrations/src/cli.ts`, por lo que el rojo esperado es de compilación: ambos tests nuevos deben fallar con `TS2307` para `../src/cli`. No se agrega un stub ni implementación antes de la revisión del desarrollador.

## Primera verificación de la segunda implementación y corrección — 2026-09-29

El desarrollador ejecutó el chequeo TypeScript del consumidor y volvió al prompt sin diagnósticos. Luego ejecutó la suite del consumidor: **60 passing, 1 failing**. Los dos contratos de script/CI pasaron; el único fallo fue `README.md is stale` dentro de `docs:check`. La causa es de portabilidad del checkout: `.gitattributes` permite EOL nativo y el checkout Windows presenta CRLF, mientras el generador construía LF y comparaba bytes de texto sin normalizar EOL. El contenido generado era equivalente, pero el checker lo clasificaba erróneamente como stale.

El `test-integration` compiló pero falló de forma bloqueante, como exige el contrato, con `migration.environmentMismatch`: `psql` no pudo resolver el hostname `postgres`. El script no hizo skip ni sustituyó la versión. El problema observado pertenece a la orquestación Compose local: `node` declara `PGHOST=postgres`, pero no exigía que el servicio `postgres` estuviera arrancado y healthy al iniciar `node`.

Corrección preparada dentro del alcance ya aprobado del segundo rojo:

- `generate-readme.js --check` normaliza únicamente EOL de texto (`CRLF`/`CR` a `LF`) antes de comparar con la salida canónica; no relaja contenido, ejemplos ni marca GENERATED;
- `compose.yaml` hace que `node` dependa de `postgres` con `condition: service_healthy`, manteniendo `PGHOST=postgres`;
- el contrato T17 comprueba estáticamente esa dependencia/host para evitar regresión de la integración local.

La verificación T17 permanece pendiente. Debe reconstruirse/recrearse el entorno Compose y repetirse typecheck, suite consumidor, `docs:check`, `test-integration` y suite raíz antes de marcar verde.
