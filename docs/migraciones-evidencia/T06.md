## Implementación

Archivos principales:

- `consumers/postgres-migrations/src/artifact.ts`: tipos de manifest/environment/data, SHA-256, materialización canónica, publicación inmutable y loader verificado.
- `consumers/postgres-migrations/src/index.ts`: barrel público del consumidor.
- `consumers/postgres-migrations/package.json` y `package-lock.json`: dependencia local explícita del paquete raíz.
- `consumers/postgres-migrations/scripts/bootstrap-repository.js`: en tests/build del checkout crea sólo un link local en el `node_modules` raíz para resolver `system-definition`; no descarga dependencias ni importa fuentes privadas. En Docker ese directorio es el volumen Linux de dependencias, no el bind mount Windows del checkout.
- `.gitattributes`: `*.sql text eol=lf` para que recursos SQL byte-addressed no cambien por checkout.

Propiedades implementadas:

- `sha256Hex` hashea `Uint8Array` exactos y produce hex lowercase.
- `computeReleaseHash` canonicaliza el manifest quitando únicamente `release.releaseHash`; IDs, paths, hashes de archivos, environment, generator e inspector siguen cubiertos.
- snapshot, persistence, schema, create-plan y environment se publican como JSON canónico UTF-8 sin newline agregado; `FileInfo` fija hash y longitud de bytes.
- recursos SQL/check conservan bytes UTF-8 exactos; BOM y CR/CRLF se rechazan en vez de normalizarse.
- paths de artifacts deben ser relativos y no contener `..`, separadores Windows ni colisiones case-insensitive; el loader recorre componentes con `lstat` y rechaza symlinks.
- publicación de un mismo ID+contenido es idempotente; mismo ID con contenido distinto no sobrescribe historia.
- el loader valida primero manifest/releaseHash, metadata/hashes de archivos y bytes de recursos antes de devolver un artifact utilizable.
- el artifact cargado se reconstruye exclusivamente desde archivos históricos; mutar el draft/Def vivo después de publicar no altera lo cargado.

## Verificación autoritativa

El desarrollador ejecutó en Docker Node 24:

```powershell
docker compose exec node npm test
```

Resultado observado: **exit 0**. El comando encadena el core y el consumidor separado:

- core `system-definition`: **146 passing (131ms)**;
- `@system-definition/postgres-migrations`: **9 passing (105ms)**.

Los 9 casos del consumidor cubren hash de bytes exactos, `releaseHash` sin self-cycle, publicación idempotente/inmutable, detección de SQL alterado, rechazo de paths/case collisions, symlink escape, BOM/CRLF, carga histórica independiente de Def viva y manifest alterado.

El primer intento de contrato focalizado usó `--ignoreConfig` sobre un archivo del consumidor. Ese comando no era válido para este paquete porque al ignorar `tsconfig.json` también eliminaba los typings/globals de Node y produjo diagnósticos sobre `node:crypto`, `node:fs/promises`, `node:path`, `TextEncoder`, `NodeJS` y `process`. No fue un fallo de la implementación.

Se corrigió la verificación para compilar el proyecto del consumidor con su configuración real:

```powershell
docker compose exec node `
  npx tsc `
  -p consumers/postgres-migrations/tsconfig.json `
  --noEmit
```

Resultado observado: **exit 0, sin salida ni diagnósticos**.

Con el suite completo y el typecheck del proyecto verdes se marca **Verificación** de T06. La revisión final del desarrollador permanece pendiente.
