## Implementación

Archivos de producción:

- `src/common/json-value.ts`
  - `JsonValue` según el contrato.
  - `toJsonValue(unknown)` valida y copia sin aliases hacia la fuente.
  - inspección mediante property descriptors, sin ejecutar getters/setters/toJSON.
  - rechazo de `undefined`, bigint, símbolos, funciones, números no finitos, instancias no planas, ciclos, huecos, accessors y propiedades que JSON perdería.
  - referencias compartidas acíclicas permitidas usando una pila/conjunto de ancestros, no un conjunto global de visitados.
  - objetos copia con prototipo nulo para que `__proto__` sea dato ordinario.
  - problemas `migration.invalidJson` bloqueantes con `details.path` y `details.reason`.
  - `canonicalJson(JsonValue)` revalida entradas externas casteadas y lanza `TypeError` si son inválidas.
  - canonicalización sin whitespace/newline, arrays en orden y objetos con keys ordenadas lexicográficamente por unidades UTF-16; strings y números se emiten con `JSON.stringify`, por lo que `-0` queda `0` y Unicode no se normaliza.
- `src/common/index.ts`: export público de `json-value`.

## Verificación en este sandbox

Este sandbox no tiene Docker y su `node_modules` no contiene las dependencias declaradas del repo (`@types/node`, `@types/mocha`), por lo que `npm test` no puede ser la verificación final aquí.

```sh
npx tsc --noEmit --strict --target es2022 --module nodenext --moduleResolution nodenext --lib esnext src/common/problem.ts src/common/json-value.ts
```

Resultado: exit code 0.

También se compiló temporalmente `problem.ts` + `json-value.ts` a CommonJS y se ejecutó un harness runtime equivalente a los criterios T01. Resultado:


El harness cubrió copia sin alias a la fuente, referencias compartidas acíclicas, tipos no JSON, NaN/infinito, arrays con huecos, clase/ciclo, getters/setters/toJSON no ejecutados, `__proto__`, keys numéricas, null/string vacío/`-0`, Unicode, casts externos inválidos, symbol keys, propiedades no enumerables y propiedades extra de arrays.
