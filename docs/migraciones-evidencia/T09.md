# Evidencia T09 — Objetos adicionales y datos administrados

## Alcance del rojo

T09 depende de T08. El desarrollador cerró T08 con `T08 approved` antes de iniciar este trabajo.

Se agregaron pruebas de aceptación en el consumidor separado para dos contratos inicialmente ausentes: preparación/validación de recursos de creación adicionales y checker de datos administrados. El rojo fue ejecutado por el desarrollador y mostró únicamente 4× `TS2307` para `../src/create-resources` y `../src/managed-data`; fue aprobado explícitamente con `T09 red approved` el 2026-09-28.

Las pruebas cubren:

- orden topológico de `CreateResourceInfo` con desempate estable por ID y rechazo de ciclos, dependencias ausentes e IDs duplicados;
- inspección de vistas y rutinas mediante deparsers PostgreSQL, además de checks e índices;
- cambio semántico del cuerpo de una rutina/vista como diferencia estructural legible;
- validación de `expectedObjects` y bloqueo si el inspector reporta `unknown`;
- índice independiente extra visible como drift y backing index de constraint identificado por ownership, sin exigirlo como segundo objeto autoral;
- datos administrados comparados sólo para tabla/keys/columnas declaradas, preservando `null` frente a string vacío;
- rechazo de claves administradas duplicadas y de declaraciones cuyo `columns` no incluya la key.

## Implementación

Se agregaron:

- `consumers/postgres-migrations/src/create-resources.ts`: valida referencias SQL, IDs, dependencias y objetos esperados; ordena el grafo de recursos de creación topológicamente con desempate UTF-16 estable; `validateExpectedObjects` exige la presencia exacta de cada identidad declarada y bloquea inventario `unknown`.
- `consumers/postgres-migrations/src/managed-data.ts`: valida declaraciones/keys/columnas, detecta claves duplicadas, consulta sólo columnas y keys administradas mediante parámetros y compara valores de máquina preservando `null` y `''` como distintos. No usa `SELECT *` ni exige igualdad de filas de usuario ajenas.
- `inspect-schema.ts`: amplía el inventario PostgreSQL con vistas (`pg_get_viewdef`) y rutinas (`pg_get_functiondef`) y mantiene aggregates/window functions como inventario no soportado/`unknown`; checks e índices continúan preservando definición y ownership del backing index.
- `src/index.ts` del consumidor exporta los dos contratos nuevos.
