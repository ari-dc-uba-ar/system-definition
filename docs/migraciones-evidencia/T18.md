## Segundo rojo propuesto — replay/historia/drift/SSOT

Archivo nuevo: `consumers/postgres-migrations/test/authoring-history-test.ts`.

La nueva frontera esperada vive en `src/authoring-history.ts`; el rojo no crea ese módulo. Contrato fijado:

1. `reconstructHistory(...)` recibe source/head/path/journal/scope/contexto ya existentes y `ScratchProvider`; debe reutilizar el harness T13/runner real, no aceptar un esquema "esperado" devuelto por un mock como sustituto del replay;
2. el fixture histórico A→B ejecuta el SQL publicado y devuelve el esquema B, demostrando que el replay pasó por la ruta de migración y que todo scratch propio se limpia;
3. el mismo replay sin `SET NOT NULL` debe fallar `migration.schemaDrift` porque no alcanza el `historyHead` registrado, aun cuando los checks de datos puedan pasar;
4. `checkHistoryHeadDrift(historyHead, observed)` compara una instalación contra su **propio** head confirmado: A observado contra A pasa aunque el catálogo/deseado ya sea B; A esperado contra B observado bloquea con `migration.schemaDrift`;
5. `requireDesiredRelease(null)` bloquea con `migration.invalidReference`; una release SSOT explícita sí se conserva. `observed` nunca se adopta como desired.

El rojo esperado es de compilación por un único módulo de producción intencionalmente inexistente: `../src/authoring-history`. No se autoriza implementarlo hasta revisión explícita. Este corte no intenta todavía el plan residual/`compileDraft`; esa parte seguirá con un red separado dentro de T18.
