## Primer rojo propuesto

Archivo nuevo: `consumers/postgres-migrations/test/infer-test.ts`.

Contrato que fija:

1. firma pública exacta de `inferStructureChanges` con `ValidationResult<readonly StructureChangeInfo[]>`;
2. columna nullable nueva → `add / inferred / preserving`;
3. columna nueva `NOT NULL` → `requiresDataCheck`, sin inventar relleno;
4. rename con nombres semejantes **no** se adivina: sin correspondencia explícita queda `remove` destructivo + `add` preserving;
5. rename explícito y biyectivo se representa como `rename` preserving cuando el resto de atributos coincide;
6. nullable→NOT NULL → `alter / requiresDataCheck`; NOT NULL→nullable → `alter / preserving`; DROP columna → `destructive`;
7. IDs y orden son determinísticos ante distinto orden del inventario físico;
8. los IDs cambian si cambia el `AuthoringBaseInfo`, demostrando que una decisión de otro par snapshot/mapping no autoriza este diff.

El rojo esperado es de compilación porque aún no existen `src/authoring-contract.ts` ni `src/infer.ts`. No se autoriza crear esos módulos hasta revisar este rojo.
