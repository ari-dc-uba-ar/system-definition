# Evidencia T22 — integración completa de autoría y deployment

## Rojo #1 propuesto — artifact inmutable de autoría y `migrationHash` — 2026-10-01

T21 quedó cerrada después de `T21 approved`. El primer slice T22 se limita al contrato de artifact inmutable de una migración publicada descrito en `migraciones-autoria-contratos.md`: el manifest persistido debe llevar `authoring: FileInfo`, cuyos bytes son el `CompiledAuthoringInfo`; `migrationHash` cubre todo el manifest salvo su propio campo, de modo que cambiar la referencia/hash del authoring invalida la identidad de la migración.

### Alcance del rojo

Se añade sólo `consumers/postgres-migrations/test/authoring-artifact-test.ts`. No se modifica producción. El rojo exige:

1. `computeMigrationHash` omite únicamente `migrationHash` y cambia si cambia `authoring.contentHash`;
2. `decodeMigrationManifest` exige `authoring: FileInfo`, acepta el manifest válido y devuelve copia desacoplada;
3. no existe ruta legacy que acepte una migración publicada sin manifest de autoría;
4. metadata de `authoring` insegura o mal formada falla en el boundary del artifact;
5. cambiar `authoring` conservando un `migrationHash` viejo produce `migration.checksumMismatch`.

El contrato reaprovecha `FileInfo`, JSON canónico, SHA-256 y reglas de paths de `artifact.ts`; no crea otro algoritmo de hashing.

### Rojo esperado

Contra la producción T21 actual el test no debe compilar, porque `artifact.ts` todavía no exporta la frontera T22:

```text
error TS2305: Module '"../src/artifact"' has no exported member 'computeMigrationHash'.
error TS2305: Module '"../src/artifact"' has no exported member 'decodeMigrationManifest'.
```

Ese fallo es deliberado: T21 dejó explícitamente fuera persistencia `authoring: FileInfo` y hashes de migration artifacts.

### Fuera de autorización de este slice

No quedan autorizados todavía:

- resolver/cargar los bytes de `authoring.json` desde `buildMigrationPlan`;
- ampliar `PublishedMigrationInfo`, `MigrationPlanInfo` o `planHash` para consumo del runner;
- ligar checkpoints/queries/validadores a verification evidence o deployment gates;
- cambios CLI/CI/non-interactive;
- fixtures email transferido/nota descartada ni matriz PostgreSQL real;
- cualquier trabajo T23.

Si el desarrollador responde explícitamente `T22 first red approved`, la implementación debe limitarse a esta frontera de manifest/hash inmutable y sus regresiones directas.

## Rojo #2 propuesto — loader de authoring, `buildMigrationPlan` y `planHash` — 2026-10-01

Este slice conecta el manifest inmutable del rojo #1 con la frontera de planificación descrita por los contratos: `resolveMigrationPath` sigue puro en core y el consumidor debe cargar/verificar los artifacts exactos antes de firmar el segmento con `planHash`.

### Alcance del rojo

Se añade sólo `consumers/postgres-migrations/test/migration-plan-artifact-test.ts`; no se modifica producción. El rojo exige:

1. `computePlanHash` cubre todo `MigrationPlanInfo` salvo su propio `planHash`;
2. el plan vacío conserva `from/to` exactos y no consulta artifacts de migración;
3. para cada transición, `buildMigrationPlan` carga el manifest por la identidad publicada, verifica que coincide con el path y lee los bytes exactos de `authoring: FileInfo`;
4. hash, longitud y JSON canónico de `authoring.json` se verifican antes de firmar el plan;
5. el `base.from/to` del `CompiledAuthoringInfo` debe coincidir exactamente con los endpoints de la migración;
6. `planHash` queda ligado transitivamente a `migrationHash`, y éste ya incluye `authoring.contentHash`.

### Rojo esperado

Contra la producción del slice #1 el test debe fallar en TypeScript porque todavía no existe el módulo consumidor de planificación:

```text
error TS2307: Cannot find module '../src/migration-plan' or its corresponding type declarations.
```

### Fuera de autorización de este slice

No se autoriza todavía:

- resolver queries/validadores/checkpoints en `MigrationExecutionContext` ni cambiar el runner;
- ligar `planHash`/artifacts a verification evidence, rehearsal o deployment gates;
- CLI/CI/docs generadas más allá del handoff;
- matriz generated/manual/mixed con PostgreSQL 18.6 real;
- trabajo T23.

Si el desarrollador responde `T22 second red approved`, la implementación debe limitarse al loader verificable de manifest/authoring, `buildMigrationPlan` y `planHash`.
